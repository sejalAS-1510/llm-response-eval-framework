# Data Models & Schemas Reference

## Overview

The framework relies on strictly validated Pydantic v2 data models for input validation, inter-agent communication, persistent storage, and report generation. This document details the schema contracts across all system layers.

---

## 1. Input Module Schemas ([`src/input_module/schemas.py`](file:///C:/Sejal/Infosys%20Springboard/llm-response-eval-framework/src/input_module/schemas.py))

### `EvaluationSubmission`
Payload submitted by clients for single-response evaluation.

```python
class EvaluationSubmission(BaseModel):
    question: str = Field(..., min_length=1, description="The prompt or question presented to the AI")
    ai_response: str = Field(..., min_length=1, description="The response generated by the AI model")
    reference_answer: Optional[str] = Field(None, description="Optional ground-truth reference answer")
    source_document: Optional[str] = Field(None, description="Optional raw context document")
    model_name: Optional[str] = Field("unknown", description="Identifier of the model being evaluated")
```

### `ClaimEvaluation` & `HallucinationResult`
```python
ClaimStatus = Literal["supported", "unsupported", "contradicted"]

class ClaimEvaluation(BaseModel):
    claim: str = Field(..., description="Discrete atomic factual claim")
    status: ClaimStatus
    evidence: Optional[str] = Field(None, description="Quoted passage from context if supported/contradicted")
    explanation: str

class HallucinationResult(BaseModel):
    is_hallucinated: bool = Field(..., description="True if any claim is unsupported or contradicted")
    hallucination_score: float = Field(..., ge=0.0, le=1.0, description="Fraction of claims unsupported")
    total_claims: int
    unsupported_claims_count: int
    flagged_claims: List[ClaimEvaluation]
    all_claims: List[ClaimEvaluation]
    reasoning: str
```

### `VerdictResult`
```python
VerdictCategory = Literal["Pass", "Needs Improvement", "Fail"]

class VerdictResult(BaseModel):
```

### `EvaluationResult`
Unified container aggregating input data, resolved context, individual agent assessments, and the final verdict:


## 4. Reporting & PDF Aggregator Schemas ([`src/reporting/schemas.py`](file:///C:/Sejal/Infosys%20Springboard/llm-response-eval-framework/src/reporting/schemas.py))

### `BatchReportData`
The consolidated data object that feeds the ReportLab PDF generator:

```python
class BatchReportData(BaseModel):
    metadata: ReportMetadata
    overall_stats: OverallStats
    hallucination_frequency: HallucinationFrequency
    per_response_details: List[PerResponseReportDetail]
    recommendations: List[RecommendationItem] = Field(default_factory=list)
```

#### Supporting Report Elements
- **`ReportMetadata`**: Batch ID, filename, creation timestamp, generation timestamp, record counts.
- **`OverallStats`**: Pass/Needs/Fail counts and percentages, plus average score and percentage for every dimension (Relevance, Accuracy, Completeness, Groundedness, Weighted Score).
- **`HallucinationFrequency`**: Count of flagged responses, total claims extracted, total ungrounded claims, and representative sample strings.
- **`RecommendationItem`**: Actionable improvement recommendation containing `id`, `category`, `priority`, `headline`, `plain_english`, `metric_trigger`, `remediation_advice`, `affected_count`, `affected_percent`, and `sample_issues`.
- **`PerResponseReportDetail`**: Granular item representation including full prompt, response, reference, status, dimensional score breakdown, flagged hallucinated claims, and missing aspects.
